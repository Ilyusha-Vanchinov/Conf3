# УВМ — вариант 6. Ассемблер и интерпретатор

## Общее описание

Проект реализует ассемблер и интерпретатор для учебной виртуальной
машины (УВМ), вариант 6. Работа выполняется поэтапно; каждый этап
фиксируется отдельным коммитом в git-репозитории.

Текущее состояние: **этап 1** — CLI-ассемблер, который разбирает
текстовый файл программы на языке ассемблера и строит промежуточное
представление (список инструкций). Генерация машинного кода и
интерпретатор будут добавлены на следующих этапах.

## Структура репозитория

```
.
├── README.md
├── .gitignore
├── run.bat
├── requirements.txt
├── src/
│   ├── __init__.py
│   ├── isa.py
│   └── assembler.py
├── tests/
│   ├── __init__.py
│   └── test_assembler.py
└── examples/
    └── spec_tests.asm
```

- `src/isa.py` — описание системы команд УВМ: коды операций,
  допустимые диапазоны операндов, класс `Instruction`.
- `src/assembler.py` — CLI-ассемблер: разбор `.asm` в промежуточное
  представление и режим тестирования.
- `tests/test_assembler.py` — модульные тесты ассемблера.
- `examples/spec_tests.asm` — тестовая программа из спецификации УВМ.
- `run.bat` — скрипт запуска для Windows.

## Язык ассемблера

Синтаксис строки:

```
мнемоника операнд
```

Правила:

- комментарий начинается с символа `;` и продолжается до конца строки;
- пустые строки игнорируются;
- мнемоники регистронезависимы;
- операнд — целое число в десятичной (`463`) или шестнадцатеричной
  (`0x1CF`) форме.

Поддерживаемые команды:

| Мнемоника    | Код A | Операнд B    | Диапазон B       |
|--------------|-------|--------------|------------------|
| `load_const` | 41    | константа    | 0…8191           |
| `load_mem`   | 25    | адрес памяти | 0…33 554 431     |
| `store_mem`  | 49    | смещение     | 0…255            |
| `sub_mem`    | 30    | адрес памяти | 0…33 554 431     |

## CLI ассемблера

```
python -m src.assembler <source.asm> <output.bin> [--test]
```

Аргументы и настройки:

- `source.asm` — путь к исходному файлу программы на языке ассемблера;
- `output.bin` — путь к бинарному файлу-результату. На этапе 1 файл
  не формируется; аргумент принимается для совместимости с CLI
  следующих этапов;
- `--test` — включить режим тестирования: вывести промежуточное
  представление программы в виде полей `A` и `B`.

## Режим `--test`

В режиме тестирования для каждой команды печатается строка:

```
<МНЕМОНИКА>: A=<код>, B=<операнд>
```

Это соответствует тестам из спецификации УВМ: демонстрирует, что
ассемблер строит внутреннее представление с теми же полями и
значениями.

## Пример использования

Файл `examples/spec_tests.asm`:

```asm
; Тестовые команды из спецификации УВМ (вариант 6)
load_const 463
load_mem 1002
store_mem 122
sub_mem 993
```

Запуск в Windows:

```
run.bat assemble examples\spec_tests.asm out.bin --test
```

Эквивалентная команда без `run.bat`:

```
python -m src.assembler examples/spec_tests.asm out.bin --test
```

Ожидаемый вывод:

```
LOAD_CONST: A=41, B=463
LOAD_MEM: A=25, B=1002
STORE_MEM: A=49, B=122
SUB_MEM: A=30, B=993
```

## Сборка и запуск тестов

Требования:

- Python 3.10 или новее;
- `pytest` (устанавливается из `requirements.txt`).

Установка зависимостей:

```
pip install -r requirements.txt
```

Запуск тестов в Windows:

```
run.bat test
```

Эквивалентная команда без `run.bat`:

```
python -m pytest tests/ -q
```

## Этап 2 — формирование машинного кода

Ассемблер переводит промежуточное представление в машинный код
и записывает результат в бинарный файл.

### Формат команды

Каждая команда — 4 байта, little-endian. 32-битное слово:

```
word = (B << 6) | A
```

где `A` — код операции (биты 0—5), `B` — операнд (старшие биты,
ширина зависит от команды).

### CLI

```
python -m src.assembler <source.asm> <output.bin> [--test]
```

- `output.bin` — бинарный файл с машинным кодом;
- программа печатает `Binary size: <N> bytes`;
- `--test` дополнительно печатает байты каждой команды
  в формате, как в тестах из спецификации УВМ.

### Пример

```
run.bat assemble examples\spec_tests.asm out.bin --test
```

Ожидаемый вывод:

```
Binary size: 16 bytes
load_const 463 (A=41, B=463): 0xE9, 0x73, 0x00, 0x00
load_mem 1002 (A=25, B=1002): 0x99, 0xFA, 0x00, 0x00
store_mem 122 (A=49, B=122): 0xB1, 0x1E, 0x00, 0x00
sub_mem 993 (A=30, B=993): 0x5E, 0xF8, 0x00, 0x00
```

## Этап 3 — интерпретатор и модель памяти

### Модель памяти

- Память — единый массив 32-битных ячеек (`list[int]`), по умолчанию
  `2^20` ячеек.
- Память команд и память данных объединены: программа загружается
  с адреса `0`, данные располагаются по любым свободным адресам.
- Стек — отдельный список Python (не часть памяти, не попадает в дамп).
- `PC` — номер текущей ячейки; интерпретация идёт линейно, пока `PC`
  меньше длины загруженной программы.

### CLI интерпретатора

```
python -m src.interpreter <program.bin> <dump.json> <start> <end>
```

- `program.bin` — бинарный файл с ассемблированной программой;
- `dump.json` — путь к файлу, куда будет сохранён дамп памяти;
- `start` — начальный адрес (включительно);
- `end` — конечный адрес (не включительно).

### Формат JSON-дампа

```json
{
  "start": 100,
  "end": 106,
  "memory": {
    "100": 10,
    "101": 20,
    "102": 30,
    "103": 40,
    "104": 50,
    "105": 60
  }
}
```

### Реализованные команды

| Команда       | Действие                                                      
|---------------|---------------------------------------------------------------
| `load_const B`| положить константу `B` на стек                                
| `load_mem B`  | положить `memory[B]` на стек                                  
| `store_mem B` | снять адрес и значение со стека, записать в `memory[addr + B]`

`sub_mem` реализуется на этапе 4; при вызове интерпретатор бросает
`NotImplementedError`.

### Пример: копирование массива

Файл `examples/copy_array.asm`:

1. инициализирует массив в адресах `100..105` значениями
   `10, 20, 30, 40, 50, 60` (`load_const` + `store_mem`);
2. копирует его в адреса `200..205` (`load_mem` + `load_const` +
   `store_mem`).

Сборка и запуск:

```
run.bat assemble examples\copy_array.asm copy_array.bin
run.bat interpret copy_array.bin dump_src.json 100 106
run.bat interpret copy_array.bin dump_dst.json 200 206
```
